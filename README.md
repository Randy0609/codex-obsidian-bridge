## 这解决什么问题

大多数老板用 AI 的现状:**聊天框式用 AI**——复制一段资料、问一个问题、得到一段回答、再手动搬回自己的文档。资料散落在微信、网盘、笔记本里,AI 每次都从头了解你的业务。

这个仓库提供另一条路:

```
你的知识库(Obsidian,本地 Markdown 文件)
        ↕  一套目录约定 + 一份 AGENTS.md 上岗手册
你的 AI 员工(Codex,能读写文件、执行任务、交付结果)
```

打通之后,变化是:

- **业务背景可持续沉淀**:资料放在固定位置,AI 按任务读取,不用每次重新交代(不需要自动加载全部知识,读该读的)
- **从"问答"到"交付"**:你说需求,AI 产出成品文档放进交付区,而不是聊天框里一段话
- **本地保存,处理可控**:笔记保存在你选择的本地文件夹;使用云端模型时,被读取的内容会作为上下文发给模型服务,处理范围由你授权
- **结果可检查**:AI 每次干完活留下交付物和纪要,做得好不好、依据是什么,一眼能查

## 这套东西的来源

这不是理论框架,是一套**在真实电商业务中日常使用**的工作方式:知识库支撑经营日报、会员运营、内容生产,多个不同分工的 Codex 席位在同一个知识库里协作。本仓库只讲**通用的方法和模板**,不包含任何业务数据;文中的案例数字均来自一次真实知识库的结构盘点,已做完全脱敏。

## 拿到这套教程的三种方式

1. **网页直接看**(最简单):你现在这样读下去就够了,提示词都是可复制的
2. **下载到本地**:仓库页右上角绿色 **Code → Download ZIP**,解压后先看 `README.md`,模板在 `templates/` 里;**下载教程 ≠ 导入知识库**,模板复制进你自己已有的库时,已有文件不要覆盖

## 用起来是什么样(日常工作流)

```
00_收件箱/          ← 随手扔:语音转写、聊天记录、灵感、截图
01_任务包/          ← 你派活:每个任务一个文件夹(需求+验收标准)
02_交付物/          ← AI 交活:成品文档,你验收
03_会话记忆/        ← AI 记事:每次干活的纪要(不等于 Codex 系统记忆)
```

一句话:**你往收件箱扔原料、在任务包写需求,AI 在交付物交成品、在会话记忆记笔记。** → [日常工作流详解](docs/03-日常工作流.md)

## 适合谁

- **中小企业经营者/老板**:想用 AI 但不想把公司数据交给云端保管
- **AI 组织的合伙人**:帮企业搭建和管理 AI 团队的超级个体、顾问、操盘手——你手上有若干 AI 席位要带,这套目录约定和上岗手册就是你的施工标准与交付规范
- **一个人当一支队伍用的超级个体**:电商、咨询、自媒体、专业服务
- **团队的"AI 推广负责人"**:想给老板/同事一套不依赖技术的落地方法

**不需要会写代码。** 全程只用三样东西:Obsidian(个人使用免费)、Codex、一套文件夹约定。

## 这套方法做不到什么(诚实版)

- **不自动导入你的历史**:旧项目资料需要你选择、整理、核对,本仓库不扫描、不承诺完整导出任何历史记录
- **不训练模型**:整理资料不会让模型"学会"你;AI 的表现来自每次开工读了哪些文件
- **本地保存 ≠ 全程离线**:使用云端模型时,被读取的内容会作为上下文发送给模型服务
- **不承诺经营效果**:方法能减少重复交代、让工作有据可查,具体业务效果取决于你的使用
