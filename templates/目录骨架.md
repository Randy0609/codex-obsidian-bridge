# 目录骨架 · 一套可直接抄的 vault 结构

> 用法:在你的 Obsidian vault 里照着建目录,把每个目录下的「使用说明」复制存成该目录里的 `使用说明.md`。四个核心目录跑顺了,再按需扩展。

## 最小可用版(先跑通这四个)

```
我的公司知识库/
├── AGENTS.md            ← AI 员工上岗手册(见 templates/AGENTS.md)
├── 00_收件箱/
│   └── 使用说明.md
├── 01_任务包/
│   └── 使用说明.md
├── 02_交付物/
│   └── 使用说明.md
└── 03_会话记忆/
    └── 使用说明.md
```

## 各目录使用说明(复制即用)

### 00_收件箱/使用说明.md

```markdown
# 收件箱使用说明

这里扔原料,不做任何整理:
- 会议/通话录音的转写文字
- 微信重要聊天记录(全选复制即可)
- 灵感、想法、随手记
- 值得留存的网页摘录、客户反馈

规矩:
1. 只管扔,别整理——整理是 AI 的活
2. 文件名随手起,带日期最好:0920-老李电话.md
3. 每周对 AI 说一次:"整理收件箱,给出归档建议"
```

### 01_任务包/使用说明.md

```markdown
# 任务包使用说明

这里写任务书,一个任务一个文件,命名 MMDD-任务名.md。

任务书三段式:
## 需求 —— 做什么、给谁看、解决什么问题
## 交付 —— 成品放哪、叫什么、什么格式
## 验收标准 —— 可检查的硬标准(数字有出处、格式照某样例)

心法:当新来的聪明员工带——背景说清,标准给足,别管过程。
```

### 02_交付物/使用说明.md

```markdown
# 交付物使用说明

AI 的所有成品只放这里,命名 MMDD-交付物名.md,与任务书对应。

规矩:
1. 我只验收这个文件夹,成品不许散落别处
2. 不合格 → 退回,在原任务书里补要求重做
3. 好的成品可以当"样例",以后任务书里直接引用它的格式
```

### 03_会话记忆/使用说明.md

```markdown
# 会话记忆使用说明

AI 每次干完活在这里写纪要:MMDD-纪要.md,10 行以内:
- 做了什么
- 发现了什么
- 下次要注意什么

每周让 AI 回顾全部纪要,把教训沉淀成规则,报批后写进 AGENTS.md。
这是 AI 越用越懂你的关键。
```

## 进阶扩展(跑顺一个月后再加)

```
10_业务数据/     ← 日报、周报、经营数据的固定落点(每天同一文件名,AI 自动读)
20_客户与关系/   ← 客户档案一人一页;敏感的话把整个目录设为禁区
30_内容库/       ← 选题、素材、成稿、已发布,一条流水线
40_制度与SOP/    ← 公司规矩、流程文档;AGENTS.md 可直接引用
90_禁区/         ← 财务、核心名单等敏感资料,AI 禁入
```

> 原则:**从四个目录开始,用出痛了再加**。目录不是越多越好,是 AI 和你都能记住才好。
