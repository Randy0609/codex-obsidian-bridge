# 目录骨架 · 一套可直接抄的 vault 结构

> 用法:已连接用户请从 [docs/06-用一个旧项目开始](../docs/06-用一个旧项目开始.md) 走流程,Codex 提示词会按用途**复用你已有的目录**,不会强行重命名。下面的结构是推荐起点,名称可调整,但**全库只保留一套结构**。

## 推荐起点(从这九样开始)

```
我的知识库/
├── AGENTS.md          ← 开工规则:入口、事实、写入边界(AI 每次开工自动读)
├── 首页.md            ← 你和 AI 共用的导航(开工第一眼)
├── 00_收件箱/         ← 原料与待确认内容:转写、聊天记录、灵感,只扔不整
├── 01_任务包/         ← 需求与验收标准,一个任务一个文件
├── 02_交付物/         ← 任务结果,AI 只在这里放成品
├── 03_会话记忆/       ← 工作纪要(注意:不等于 Codex 系统记忆)
├── 10_关于我/         ← 角色、当前目标、协作偏好
├── 20_项目/           ← 项目现状、已确认决定、下一步与来源
└── 30_方法/           ← 可复用的方法(需要时再建,不急)
```

## 各目录使用说明(复制即用)

### 00_收件箱/使用说明.md

```markdown
# 收件箱使用说明

这里扔原料,不做任何整理:
- 会议/通话录音的转写文字、微信重要聊天记录、灵感、网页摘录、待确认的交接稿

规矩:
1. 只管扔,别整理——整理是 AI 的活
2. 文件名带日期:2026-09-20-老李电话.md
3. 每周对 AI 说一次:"整理收件箱,给出归档建议"
```

### 01_任务包/使用说明.md

```markdown
# 任务包使用说明

一个任务一个文件,命名 YYYY-MM-DD-任务名.md(同名不覆盖,重复加"-2")。

任务书三段式:
## 需求 —— 做什么、给谁看、解决什么问题
## 交付 —— 成品放哪、叫什么、什么格式
## 验收标准 —— 可检查的硬标准(数字有出处、格式照某样例)

心法:当新来的聪明员工带——背景说清,标准给足,别管过程。
```

### 02_交付物/使用说明.md

```markdown
# 交付物使用说明

AI 的所有成品只放这里,命名 YYYY-MM-DD-交付物名.md,与任务书对应;同名不覆盖。

规矩:
1. 我只验收这个文件夹,成品不许散落别处
2. 不合格 → 退回,在原任务书里补要求重做
3. 好的成品可以当"样例",以后任务书里直接引用它的格式
```

### 03_会话记忆/使用说明.md

```markdown
# 会话记忆使用说明

AI 每次干完活在这里写纪要:YYYY-MM-DD-纪要-任务名.md,10 行以内:
- 做了什么 / 发现了什么 / 下次要注意什么

注意:这是文件里的工作记录,不等于 Codex 的系统记忆;AI 的长期本事来自"开工读首页和项目页"。

每周让 AI 回顾全部纪要,把教训沉淀成规则,报批后写进 AGENTS.md。
```

## 长期演进的参考形态(脱敏真实案例)

跑顺之后,一个真实知识库会长成这样(完整拆解见 [真实案例](../docs/05-真实案例-脱敏的知识库全景.md),目录命名因人而异,按用途对应即可):

```
我的知识库/
├── 00_收件箱/           ← 健康标志:常年只有几十篇(入口小)
├── 00_工作台/           ← 每天一篇日期笔记:派活、决策、草稿(和 AI 的每日同步协议)
├── 00_系统入口/         ← 总索引 MOC:导航到一切
├── 01_项目库/           ← 一事一夹:每个项目从立项到结案
├── 02_技能库/           ← SOP、话术、检查清单
├── 10_业务与项目/       ← 业务顶层文档(只放"正在用的刀",几十篇以内)
├── 20_内容与IP/         ← 选题、内容日历、个人品牌
├── 30_研究与知识/       ← 资产区:研究、情报,可以长到几千篇(资产厚)
├── 40_Agent与自动化/    ← AI 团队工位:每个 AI 席位一个文件夹
├── 50_个人与关系/       ← 人脉与合作方
├── 70_客户与合作/       ← 客户档案(高度敏感 → 建议不放入 AI 可及的知识库)
└── 90_归档与旧目录/     ← 只进不出
```

**健康标志**:入口小(收件箱几十篇)、操作区瘦(工作台/业务几百篇)、资产区厚(研究几千篇)。胖在资产、瘦在操作,才用得动。

## 演进路线(不要一步到位)

1. **第 1 周**:九样推荐起点,把 AI 用起来
2. **第 1 个月**:工作台(每日笔记)跑顺,项目页保持更新
3. **第 2~3 个月**:长出研究区,让 AI 批量摄入资料
4. **半年后**:自然长出自己的"AI 团队工位"——你不再是用 AI,是在带 AI 团队

> 原则:**用出痛了再加**。目录不是越多越好,是 AI 和你都能记住才好。
