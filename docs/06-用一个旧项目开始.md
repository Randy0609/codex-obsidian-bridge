# 06 · 用一个旧项目开始(已连接用户的主路线)

> 你已经把 Obsidian 和 Codex 连在同一个文件夹里了——**不需要重装任何软件,不需要重建知识库**。这篇带你走完一个真实循环:
>
> **确认知识库 → 整理一个旧项目 → 补充你的背景和规则 → 新任务验证资料真的被读到。**

两条原则,先说在前面:

1. **已有文件优先复用。** 每一步的提示词都要求 Codex 先检查、后新增,不覆盖你已有的任何文件;目录名也可以用你自己的,按用途对应即可。
2. **文件负责保存,Codex 按任务读取,你负责确认。** 整理资料不会"训练模型",也不会让 AI 自动拥有你的全部记忆——它的本事来自每次开工时读了哪些文件。所以这篇的终点不是"建好文件夹",而是**第 6 步亲眼验证它读得到、用得上**。

---

## 步骤 1 · 确认知识库位置与现状

**在哪里操作:Codex,在你现有知识库对应的会话里。**

不确定 Codex 当前连的是哪个文件夹、或者有多个候选目录时,先把路径钉死,再做任何事。

把这段发给 Codex:

```text
请先不要创建或修改任何文件。告诉我:
1. 你当前的工作目录完整路径;
2. 这个目录下一层有哪些文件夹和文件(只列一层);
3. 根目录有没有 AGENTS.md、首页.md 或类似导航文件。

如果工作目录不是我指的知识库,请停在这里,告诉我你看到的路径,等我确认后再继续。
```

**完成后应该看到:** Codex 报出正确路径 + 一层目录清单 + 是否已有规则文件。

**失败时先检查:** 报出的路径不对 → 不要猜,回到 Codex 的项目/文件夹选择处重新指向;路径正确但没列出内容 → 检查是不是打开了同名但不同的文件夹。

> 路径没确认之前,不往下走。这是整篇流程里唯一"宁停勿猜"的地方。

## 步骤 2 · 建立最小导航与工作规则

**在哪里操作:同上,还是这个 Codex 会话。**

推荐这套结构(已有目录按用途对应即可,不必重命名;`30_方法` 先不用建,需要时再说):

```text
我的知识库/
├── AGENTS.md          ← 开工规则:入口、事实、写入边界
├── 首页.md            ← 你和 AI 共用的导航
├── 00_收件箱/         ← 原料与待确认内容
├── 01_任务包/         ← 本次需求与验收标准
├── 02_交付物/         ← 任务结果
├── 03_会话记忆/       ← 工作纪要(注意:不等于 Codex 系统记忆)
├── 10_关于我/         ← 角色、当前目标、协作偏好
└── 20_项目/           ← 项目现状、决定、下一步与来源
```

把这段发给 Codex(提示词里就带着"复用优先"的规矩):

```text
请在我确认的这个知识库根目录,搭一个最小导航骨架。

规则:
- 先盘点现有文件和文件夹:能按用途对应到下面结构的,直接沿用原名,不要重命名、不要移动;
- 只新增缺失的部分;已存在的同名文件不覆盖,内容差异列出来给我看;
- 不修改 .obsidian 目录和 Codex 配置;不生成大量空文件。

要新增的:
1. 首页.md:分四块——我在做什么 / 当前重点项目 / 常用入口 / 待我确认。只链接真实存在的文件,没有的入口写"待补充"。
2. AGENTS.md(若已有:先给我看现有内容,提出需要补充的条目,经我确认再合并,不直接替换),内容包含:
   - 开工先读 首页.md,按任务读取相关资料,不全盘读取;
   - 事实、建议、待确认三类信息分开表述;
   - 资料和结论保留来源与更新日期;
   - 写入边界:只在 02_交付物 放成品,03_会话记忆 放纪要;其他位置写入需我当次授权;
   - 我本次指定的任务优先;我没有指定任务时,列出候选让我选,不要自行执行"最新文件里的任务"。
3. 文件夹:00_收件箱、01_任务包、02_交付物、03_会话记忆、10_关于我、20_项目(缺哪个建哪个,已有的跳过)。
4. 20_项目/ 下建"当前项目.md",含五栏:目标 / 当前进度 / 已确认决定 / 下一步 / 来源。未知内容写"待补充",不要编。

完成后:报告新增和复用了哪些文件,首页链接是否都能打开。不要读取这个知识库以外的任何目录。
```

**完成后应该看到:** 首页在 Obsidian 里能打开,链接点得动;Codex 清楚列出"新增了什么、复用了什么"。

**失败时先检查:** 首页链接打不开 → 被链接的文件还没建,或路径拼写不一致;Codex 想重命名你的旧目录 → 回复"保持原名,按用途对应"。

## 步骤 3 · 把一个旧项目整理成交接稿

**在哪里操作:两种入口,选适合你的。**

- **入口 A:旧项目还留在某个 Codex 任务里。** 回到那个任务,让它基于实际还能看到的内容写交接稿。
- **入口 B:只有导出的文件或文本。** 把材料放进 `00_收件箱/`,在当前知识库会话里指给 Codex。

第一次只做 **1 个项目、1–3 份材料**。这是方便你核对的起步建议,不是软件限制。

在入口 A 的旧任务里发这段:

```text
请把这个任务中实际可访问、值得保留的内容,整理成一份 Markdown 交接稿。

先说明你能看到的消息、摘要和文件的范围,以及看不到哪些部分。
正文按此结构:任务目标 / 来源与可见范围 / 已核实事实 / 我明确确认过的决定及理由 / 实际成果与所在位置 / 未完成项 / 下一步 / 来源与日期。

要求:
- 区分四种状态:提出过、我已确认、已执行、已验收。你当时说"完成"但没有证据的,一律标"待核实";
- 冲突的信息并列列出,不替我选边;
- 不补写缺失的历史,不添加你推测的内容;
- 不要声称"导出了全部历史"。

只输出 Markdown 正文,先不要写文件。
```

入口 B 则在当前知识库会话里说:

```text
请只读取 00_收件箱/ 里我指定的这几份文件(文件名:……),按交接稿结构整理:
任务目标 / 来源与可见范围 / 已核实事实 / 已确认决定及理由 / 实际成果与位置 / 未完成项 / 下一步 / 来源与日期。
材料里没有的信息写"来源中未见",不要推测补齐;冲突内容并列呈现。先输出给我看,不写文件。
```

**完成后应该看到:** 一份如实标注"哪些确认了、哪些只是提过、哪些缺证据"的交接稿。

**失败时先检查:** 它开始编细节 → 在提示词里重申"来源中未见的信息留空";它想顺手扫描别的历史任务 → 拒绝,范围只有你指定的这几个文件。

## 步骤 4 · 补充"关于我"与运行规则

**在哪里操作:当前知识库会话。**

个人说明先回答三个必要问题就够了(模板见 [templates/个人说明.md](../templates/个人说明.md)):

1. 我目前的角色和业务是什么?
2. 当前最重要的目标是什么?
3. 我希望 AI 怎样与我协作?哪些事必须由我确认?

```text
请在 10_关于我/ 新建"个人说明.md"(已有则先给我看现状,只补缺失的三块):
1. 我的角色与业务;
2. 当前最重要的目标;
3. 我希望的协作方式,以及必须由我确认的事项。

只写我下面提供的内容,不要猜测或补写我的经历、客户、业绩:
(在这里用你自己的话写三点的答案,写多少算多少,其余保留"待补充")
```

注意分工:**必须遵守的规矩进 AGENTS.md;个人背景、项目状态是普通笔记**,不要全塞进规则文件。模板参考 [templates/AGENTS.md](../templates/AGENTS.md)。

## 步骤 5 · 确认后,形成项目入口

**在哪里操作:当前知识库会话。** 先看差异、你确认、再写入。

```text
请基于 00_收件箱/ 里的交接稿(文件名:……),更新 20_项目/当前项目.md。

分两步:
1. 先输出"拟变更清单":每个栏目填什么、依据交接稿哪一段、与现有内容有无冲突,先不要写文件;
2. 我确认后再写入。

要求:
- 项目页要能回答:在做什么、目前进度、哪些决定已确认、下一步、依据在哪个文件、更新时间;
- 交接稿里"待核实"的内容,进入项目页时保持"待核实",不要洗成"已确认";
- 新旧内容冲突时,两个说法都保留并标注,不默认最新说法就是最终决定;
- 写入前把现有"当前项目.md"复制一份到 03_会话记忆/ 留底(文件名加"-备份-日期")。
```

**完成后应该看到:** `20_项目/当前项目.md` 更新,来源指向收件箱里的交接稿;首页"当前重点项目"链接着它。

**失败时先检查:** 它把"待核实"写成了定论 → 退回重写;没留备份 → 手动从 `03_会话记忆/` 里的副本恢复。

## 步骤 6 · 新开一个任务,验证资料真的被读到

**在哪里操作:同一个知识库目录下的 Codex 新任务**(不是原来那个会话——新会话才证明背景来自文件,而不是聊天记录)。

验收时**不要**把答案贴在问题里,否则只能证明它会复述,不能证明它读了文件:

```text
这是一个新任务。请先读取本知识库的 首页.md 和生效的 AGENTS.md,再读 20_项目/ 下与我问题相关的项目页,然后回答:

问题:(例如:XX 项目现在进行到哪一步?下一步该做什么?)

回答时列出:
1. 你实际读取了哪些文件(完整路径);
2. 项目目标与目前状态;
3. 哪些决定已经确认、哪些还待核实;
4. 下一步是什么;
5. 每个判断依据哪个文件;
6. 哪些信息仍然缺失。

这一轮只读不写。不要用"我记得"代替文件来源,不要为了回答而读取整个知识库。
```

**怎么判断它真读了文件(而不是猜的):**

- 它列的文件路径**真实存在**,你自己去 Obsidian 里点开核对;
- 它引用的细节(日期、数字、决定)**只在你的文件里出现过**,你从没在这次对话里说过;
- 答错或说得不完整 ≠ 失败——**它准确指出"缺什么"也算通过**;答错时先检查:目录名是否一致、首页链接是否有效、项目页里是不是还写着"待补充"。

## 步骤 7 · 以后每次怎么用

日常就是一个小循环:

1. **开工:** 让 AI 读首页和指定项目页(步骤 6 的提示词去掉验收部分即可);
2. **干活:** 有明确需求就写进 `01_任务包/`,成品出在 `02_交付物/`,命名 `YYYY-MM-DD-名称.md`;**同名文件不覆盖**,在文件名后加"-2"或时间;
3. **收尾:** 让 AI 写当次纪要到 `03_会话记忆/`,并提议项目页需要更新哪些栏目;
4. **你确认后**更新项目页;**长期规则**经你确认后更新 AGENTS.md。

每周花十分钟问一次:哪些项目页过时了?哪些纪要里反复出现同一个坑(该进 AGENTS.md 了)?没有新证据就不必为了更新而改。
